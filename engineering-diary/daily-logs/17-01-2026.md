## 💭 Key Learnings

-   **Route Naming**: Learned that `->name(...)` is optional but useful for maintainability (reverse routing), allowing URL changes without breaking code references.
-   **Form Requests**: Moved validation logic to `AuthRequest` and `ProductRequest` to handle both login and register scenarios, keeping the Controller clean (Separation of Concerns).
-   **DRY Principle (Don't Repeat Yourself)**: Reused the same `AuthRequest` class for both login and registration validation instead of writing duplicate validation rules in the controller.
-   **Separation of Concerns**: Moved validation logic out of `AuthController` and into `AuthRequest`. This keeps the controller focused on handling the request flow while the Request class handles data validation.
