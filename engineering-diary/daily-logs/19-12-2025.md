## 💭 Key Learnings

-   Configure pre-commit hooks.
    -   I learned that pre-commit hooks is a script that runs before a commit is made.
    -   The objective of pre-commit hooks:
        -   To sort of auto checks the code to be committed for any errors or warnings.
        -   Ensuring the code committed is high-quality, working code before it is committed.
-   Configure Larastan
    -   I learned that Larastan is a static analysis tool for PHP that reads your code without running it.
        -   It looking for logical errors, eg: typos, non-existent methods, or even passing data types that are not expected.
    -   The objective of Larastan:
        -   To sort of auto checks the code to be committed for any errors or warnings.
        -   Ensuring the code committed is high-quality, working code before it is committed.
-   Relationship between Manager (Husky/Hook) and Developer (Larastan).
    -   Manager (Husky/Hook) will use Larastan (Developer) to check the code before it is committed.
        -   Manager (Husky/Hook) will configure the pre-commit hooks to run Larastan before a commit is made.
        -   If Larastan finds any errors or warnings, Husky will prevent the commit from being made, and vice versa.

## 🧩 Bugs or Blockers

-   During committing the config setup, I got an error:
    ```
    🔒 [1/4] Security Check – Composer Audit
    No security vulnerability advisories found.
    husky - pre-commit script failed (code 1)
    ```
    -   I found out that the error is because of the Husky configuration, where I just commented the `npm test` line.
        -   In shell scripts (and executable files in general), the "Shebang" line (#!/bin/sh) MUST be the very first line of the file. My `pre-commit` file had `# npm test` as the first line, which pushes the shebang down. This confuses the system about how to run the file. So I removed it and commit again.
